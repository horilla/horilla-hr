{% load i18n %} {% comment %} The components in a salary structure, as a table of checkboxes. A tag box cannot say what a component does. "House Rent Allowance (HRA)" and "House Rent Allowance (Metro)" are two near-identical chips, and nothing tells you which pays half of basic and which pays a flat 1,600, or which one is the basic pay. Choosing between them meant opening each component in another screen. The columns are the same ones the structure's own listing shows, from the same summarisers, so a component reads the same before and after it is added. Rows are in (sequence, pk) order — the engine's own — so the list doubles as a preview of the order they will run in. The checkboxes post as `allowances` and `deductions`, which is exactly what the two ModelMultipleChoiceFields already expect, so the form is unchanged. {% endcomment %}
