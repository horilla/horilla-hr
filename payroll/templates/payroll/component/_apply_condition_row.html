{% load i18n %} {% comment %} One extra "when it applies" rule. Built from the same pieces as every other field on the form — a `col-* oh-component-field` cell, an `oh-component-field__label`, and the widget class the form itself uses — rather than a private grid. The inputs cannot come from `_field.html` because they are repeated and post as parallel lists, but they have no reason to look different, and a hand-rolled cell drifts the moment the form's own styling changes. Posted as apply_choices / apply_codes / apply_conditions / apply_amounts / apply_starts / apply_ends, read back by `save_apply_conditions` in payroll/forms/component_forms.py. Every row contributes to every list at the same index, so all the inputs stay in the DOM whether or not they are on screen. `data-show-scope="row"` keeps a row's own Measure and Is driving its own component and amount boxes. Without it they all share field names and would follow whichever row came first. Labels are taken from the bound fields so the extra rules read as the same kind of thing as the first one, in whatever language the form is in. {% endcomment %}
