{% load i18n %} {% comment %} Tap-to-build formula editor. Deliberately not a text box. The whole direction of this work is that the person configuring payroll should not have to know syntax to express a rule — they pick the components they mean and the operators between them, and see what it comes to. The stored value is still a plain expression string, so the engine evaluates it unchanged. Requires `formula_codes` in context (see component_formula_views.available_codes) and the form's own `formula` field, which stays in the DOM as the real input. Styled with its own scoped tokens rather than the oh-btn family: every control here is a token to tap, and rendering them as full buttons made a wall of identical primary-coloured pills with no indication of which were components, which were operators and which were numbers. {% endcomment %} {% comment %} Which field this builder writes to. Included twice on the Deduction form -- once for the component's own amount, once for the employer's share -- so the target cannot be assumed. Where the preview goes is a parameter for the same reason. On a component form there is no employee in view, so it can only be evaluated against illustrative figures; on a payslip the employee and the period are both already decided and the real ones exist. Same builder, same JSON, different context. {% endcomment %} {% url 'component-formula-preview' as fx_sample_preview_url %}
