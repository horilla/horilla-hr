{% load i18n static %} {% comment %} Load order matters here. Both of these used to fire on `load`, and the board's request fans out into one fetch per stage - so the single Nav request sat behind all of them in the queue and the toolbar (search/filter/view toggles/actions/create) did not appear until long after the stage rows were already on screen. The Nav now loads first and the board is triggered from the Nav's own htmx:afterSettle (`ohPipelineNavReady`), so the one request the user needs immediately isn't starved by the many that fill in behind it. {% endcomment %}
